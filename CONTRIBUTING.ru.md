# Руководство для контрибуторов (Contributing Guide)

Спасибо за желание сделать Metaform лучше! В этом документе описаны правила и процесс внесения изменений в проект.

# Организация ветвей

> **⚠️ Важно:** до выпуска версии `2.0` ветка `main` **не отражает текущую опубликованную в npm версию**. Это временное исключение связано с подготовкой релиза `2.0`. После выпуска `2.0` данное уведомление будет удалено, а `main` и `develop` будут работать по правилам, описанным ниже.

### Ветки разработки

Все изменения вносите в ветку `develop`. Эта ветка предназначена для текущей разработки и может содержать как новые возможности, так и изменения, которые ещё не вошли в релиз.

После выпуска версии `2.0` ветка `main` всегда будет содержать **актуальную стабильную версию библиотеки**, соответствующую последнему опубликованному релизу в npm.

Изменения из `develop` попадают в `main` только при подготовке нового релиза. Поэтому `main` не должна содержать изменений, нарушающих обратную совместимость с текущей версией `latest`.

**Кратко:**

- `develop` — вся текущая разработка и новые изменения.
- `main` — последняя стабильная версия, опубликованная в npm.
- `main` должна оставаться обратно совместимой с текущим `latest`.
- Breaking changes требуют изменения версии перед попаданием в `main`.

# Семантическое версирование

Metaform следует принципам [семантического управления версиями](https://semver.org/). Мы выпускаем исправляющие версии (`patch`) для устранения ошибок, минорные (`minor`) — для добавления новых возможностей, и мажорные (`major`) — для изменений, нарушающих обратную совместимость.

# Локальная разработка

### Требования

- **Node.js** (версия `24.19.0` или выше)
- **Пакетный менеджер:** `pnpm`

### Быстрый старт

1. Форкните репозиторий и склонируйте его локально:

```bash
git clone [https://github.com/maxqwars/metaform.git](https://github.com/maxqwars/metaform.git)
cd metaform
```

2. Установите зависимости:

```bash
pnpm install
```

3. Соберите проект:

```bash
pnpm build
```

### Полезные команды

- `pnpm dev` — запуск сборщика в режиме отслеживания изменений (watch mode).
- `pnpm test` — запуск модульных тестов с помощью Vitest.
- `pnpm test:coverage` — проверка покрытия кода тестами.
- `pnpm typecheck` — проверка типов TypeScript.
- `pnpm lint` — проверка кода линтером.
- `pnpm format` — автоматическое форматирование кода через Prettier.

> 💡 **Архитектура и структура кода:** Перед тем как писать код или добавлять новые эндпоинты, обязательно ознакомьтесь с [Архитектурным руководством (ARCHITECTURE.md WIP)](ARCHITECTURE.md). В нём подробно описаны структура файлов, паттерны DTO/Guards и чек-лист добавления нового API.

# Стандарты кода и правила коммитов

Мы используем Husky и lint-staged для проверки форматирования перед коммитом, а также следуем стандарту [Conventional Commits](https://www.conventionalcommits.org/):

`<тип>(<область>): <краткое описание>`

**Популярные типы:**

- `feat:` — новая функциональность
- `fix:` — исправление ошибки
- `docs:` — изменения в документации
- `refactor:` — переписывание кода без изменения внешнего API
- `test:` — добавление или исправление тестов

_Пример:_ `fix(core): resolve null pointer in user parsing`

# Оформление Pull Request

1. Убедитесь, что ваш PR направлен в ветку `develop`.
2. В описании PR укажите, какую проблему решает данный PR (ссылка на Issue: `Fixes #123`).
3. **Не обновляйте** версию в `package.json` и `CHANGELOG.md` — это делается централизованно при выпуске релиза.
4. Перед отправкой убедитесь, что все проверки (`pnpm typecheck`, `pnpm test`, `pnpm lint`) проходят успешно.

# Ошибки и Issues

Мы используем [GitHub Issues](https://github.com/maxqwars/metaform/issues) для отслеживания багов.

Перед созданием нового Issue убедитесь, что проблема ещё не была описана ранее. Для этого воспользуйтесь поиском по существующим Issues. Если похожий Issue уже существует, лучше дополнить его новой информацией, чем создавать дубликат.

#### Сообщение о новой ошибке

Перед созданием Issue убедитесь, что проблема воспроизводится на последней версии Metaform.
При описании ошибки постарайтесь предоставить **минимальный воспроизводимый пример (Minimal Reproducible Example)**. Чем проще воспроизвести проблему, тем быстрее мы сможем её найти и исправить.

Описание Issue должно содержать:

- краткое описание проблемы;
- ожидаемое поведение;
- фактическое поведение;
- минимальный пример кода или конфигурации, воспроизводящий проблему;
- версию Metaform;
- версию Node.js и другую информацию об окружении, если она может иметь значение.

Если проблема зависит от конкретного окружения, также укажите операционную систему и другие важные детали.
